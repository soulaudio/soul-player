QUESTIONS ANSWERED
==================

Q: "Is the 100ms fix working?"
A: Look for position update log showing "~100ms"
   - Shows "~100ms" = ✓ Fix is compiled
   - Shows "~500ms" = ✗ Rebuild

Q: "Where is latency being spent?"
A: Compare timestamps at each step
   - Frontend <5ms? Problem is backend
   - Backend <50ms? Good
   - Decoder slow? Check file format

Q: "Is ignore window working?"
A: Position updates should be suppressed after seek
   Until "Ignore window DISABLED" message appears

Q: "Is there lock contention?"
A: Lock acquisition should be <1ms
   If >5ms, audio thread might be busy

Q: "What's a reasonable seek time?"
A: ~130ms total = optimistic update + 120ms ignore window
   Backend should complete within 50ms

TROUBLESHOOTING QUICK GUIDE
===========================

No logs appearing?
  → Make sure to open DevTools (F12) BEFORE seeking
  → Ensure RUST_LOG is set for backend logs
  → Check that code was rebuilt

Logs show wrong timing?
  → Verify 100ms fix: look for "~100ms" in position update
  → If showing "~500ms", rebuild the project
  → Use TRACE level for more details

Position bar jumps back?
  → Ignore window not working
  → Check for "Ignore window DISABLED" in logs
  → Verify IGNORE_WINDOW_MS = 120

Decoder very slow?
  → Expected for MP3 VBR (20-50ms normal)
  → FLAC should be <10ms
  → Check file is not corrupt

Lock contention?
  → Lock should be acquired in <1ms
  → If >5ms, audio thread is busy (unusual)
  → Check for background processing
